## Purpose of Main Folders

| Folder | Purpose | Put here | Don't put here |
|---|---|---|---|
| `lib/core/theme/` | The design system in code | Colors, typography, spacing, ThemeData | Feature-specific styles |
| `lib/core/constants/` | Values that never change at runtime | App name, durations, limits | Secrets / API keys (go in env config later) |
| `lib/core/utils/` | Pure, stateless helpers | Formatters, validators, extensions | Code that calls the network or storage |
| `lib/core/widgets/` | Reusable widgets used by 2+ features | `AppButton`, `StatCard`, `EmptyState`, `BrandMark` | Widgets used by one feature only |
| `lib/features/<name>/` | Everything for one feature | `presentation/`, `application/`, `data/` | Imports of another feature's internals |
| `lib/services/` | App-wide infrastructure | Supabase client, notification service, local storage wrapper | UI |
| `lib/models/` | Data classes shared by features | `Mosque`, `Member`, `Donation` (when shared) | Models used by one feature only (keep in the feature) |
| `lib/routing/` | Navigation config | Routes, router, redirects, shell | Screen implementations |
| `assets/` | Bundled files | Fonts, images, icons | Large photos uploaded by users (Supabase Storage) |
| `test/` | Automated tests, mirroring `lib/` | Unit, widget, responsive tests | — |
| `docs/` | Project documentation | Planning, design, architecture | — |

## Naming Conventions

- Files: `snake_case.dart`; one public widget/class per file where practical.
- Screens end with `_screen.dart` (`prayer_times_screen.dart`); providers with `_provider.dart`; repositories with `_repository.dart`.
- Classes: `PascalCase`; reusable widgets prefixed `App…` when generic (`AppButton`), domain name otherwise (`PrayerTimeCard`).
- Imports: relative inside `lib/`, `package:masjid_management/...` in tests.

## About `.gitkeep`

Git does not track empty folders. `.gitkeep` files keep the planned feature folders in the repository. Delete a folder's `.gitkeep` when its first real file is added.
